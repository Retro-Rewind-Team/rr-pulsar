# Contributing to Retro Rewind

The rules in this file only apply to the rr-pulsar codebase **NOT** the other related retro rewind repositories. 
Members of the direct development team or select contributors selected by pack management may be exempt of the rules in this file for any reason.


Pull requests should explain what they do and what they edit. Start the description with a high-level explanation of the change and why it is needed.

## Adding New Features

Before you start adding new features, ensure that you understand:
1. **No guarantees** Your feature is not guaranteed to actually be added to Retro Rewind.
2. **Functionality is Desired:** The feature should actually be something improving Retro Rewind. Think a bug fix or a highly requested feature.
3. **Useful PRs:** Your pr should consist of re-usable and extendable code, it should be useful for futur work or other developers.
4. **Feature PR:** Submitting a PR does not give you full exclusive control over the feature, and we may reimplement any way  we see fit if your PR does not meet the standards or feature request changes.
5. **Useful Comments:** You must comment your code to explain its purpose and reasoning. **write these comments yourself**, as AI generated comments fail to explain the decisions behind the code.


## Pull Request Guidelines

Make sure your PR title starts with one of the following (or something similar):

- `fix:`
- `feature:`

Examples:

- `fix: removed goku from the game (again)`
- `feature: added new character in the game (goku)`

### PR Description

Please add these sections to your pr description

- Start with a high-level explanation of what the PR does.
- Provide testing instructions and where to find your feature.
- What you changed. Not line by line, but in general.

## AI Generated Content

If your pr uses AI-generated code, include an **AI Usage** section in the pr description. You must specify which parts were generated by AI.

Explain what AI tools you used and how you used them development, any changes you made to their output and how you reviewed and tested.

AI-generated content other than code is strictly forbidden in any contributions to Retro Rewind. This also includes documentation of your pr, pr titles and descriptions, images, and other assets. 

The allowance for AI-generated code does not extend to the text explaining that code. Your pr description must be written by you and you should be able to explain what you changed without the help of an llm.
